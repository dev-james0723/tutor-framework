## Root causes fixed

1. Semantic music-identification output could look stronger than its evidence because a single Gemini candidate was not forced through an independent corroboration gate.
2. HTTP 429 was treated differently from temporary 503 model availability, and exhausted fallback history was not preserved structurally.
3. Basic Pitch note count could promote output to probable even though the concrete adapter supplied no calibrated per-note confidence.
4. Automatic music segmentation could merge distinct lecture examples without an explicit review signal.
5. Known-score alignment availability was too close to measure/beat promotability; weak anchors could suppress provisional audio evidence even when the alignment was below threshold.

## Framework changes

- PieceIdentificationResult now carries corroboration and promotability.
- ScoreAlignmentResult now carries match score / promotion threshold / corroboration and an explicit promotable gate.
- semantic-only identification keeps a music region in requires_human_review.
- weak/unpromotable alignment no longer blocks provisional transcription/reconstruction.
- optional max_music_region_seconds review-gates suspiciously long automatic music spans.
- four provenance layers remain separate.

## Environmental incident during regression

One first full-window rerun failed because ffmpeg reported "No space left on device". The failure was traced to local disk pressure, not CAPLIN behavior. Only scratch generated by this regression attempt was removed; the original E2E evidence and source lecture files were preserved. The regression was then rerun with bounded inputs.

## Remaining truth boundary

This hardening does not make Gemini a deterministic music-recognition authority and does not make sub-0.65 DTW alignment verified. It makes those limitations explicit and fail-safe, while adding bounded course context that improved the focal Example 1 identification in this real test.
